# Post structure

- **Title**: names the outcome for the reader, under 60 characters. Not the
  internal feature name alone.
- **Description** (meta and front matter): one sentence, under 160
  characters, the outcome and who it is for.
- **Opening**: 2 to 3 sentences. What the reader can now do, and why it
  matters to them. No "we're excited".
- **One section per change**:
  1. what it does, in the reader's words;
  2. how to use it: the real steps, the exact UI labels or the command and
     its real output in a code block;
  3. one screenshot or code sample from the real product.
- **Close**: one next action (docs link, the command to try, the changelog).
- **Links**: each change's pull request or docs page; 2 to 4 internal links
  to related posts or docs.
- Length: the site's usual length. No padding to reach a word count.
